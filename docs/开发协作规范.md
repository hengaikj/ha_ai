# 开发协作规范

## 1. 统一语言

团队工程沟通统一使用中文。

必须使用中文的内容：
- Commit Message；
- Pull Request 标题、描述、Review；
- Issue 与任务说明；
- 业务代码注释、复杂算法说明、TODO/FIXME；
- 数据库表和字段 COMMENT；
- OpenAPI description 与错误说明；
- 测试报告、发布说明、部署文档、变更记录。

代码标识符继续使用规范英文：Java Package、类名、方法名、变量名、数据库表/字段、API Path 不使用中文或拼音。

## 2. Commit 规范

推荐格式：

```text
类型(模块): 中文说明
```

示例：

```text
功能(gateway): 增加 API Key 鉴权与 Redis 回源
修复(billing): 修复重复结算导致的重复扣费
测试(provider): 增加上游超时和失败计费测试
文档(api): 补充项目模型权限接口说明
重构(routing): 拆分路由决策与实际调用尝试
```

禁止只有：

```text
update
fix
test
123
修改代码
```

## 3. PR 必填内容

每个 PR 必须使用中文说明：

1. 任务编号；
2. 对应 Requirement / AC；
3. 本次实现内容；
4. 明确未实现内容；
5. 数据库/API/配置变更；
6. 自动化测试结果；
7. 真实环境验证结果；
8. 已知问题；
9. 是否偏离 Baseline。

没有证据不得写“已完成”“已通过”。

## 4. Baseline 边界

Requirement / Design / Technical Baseline 是开发输入。

如果实现需要改变已批准规则：

```text
提出变更
→ 影响分析
→ 项目负责人确认
→ 更新Baseline
→ 再实现
```

禁止开发人员为了方便自行修改业务规则。

## 5. 安全

禁止提交：
- 企业完整 API Key；
- Provider Credential；
- 支付密钥、证书私钥；
- 数据库生产密码；
- Redis生产密码；
- 任何其他生产Secret。

所有真实凭证必须通过受控环境变量或Secret管理机制提供。
