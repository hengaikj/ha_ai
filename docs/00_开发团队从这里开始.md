# 开发团队从这里开始

本项目采用“工程 Baseline 主导 + 前后端执行 Skill + Git/PR 证据闭环”的开发方式。

## 开发前必读顺序
1. 本文件
2. `docs/开发协作规范.md`
3. `docs/governance/Baseline与变更管理规范.md`
4. 自己角色对应的前端或后端启动说明
5. 当前 Milestone 任务包
6. Engineering Handoff 中对应 Requirement / Design / Technical / OpenAPI / Database / Redis / Test Contract

## 统一语言
团队统一使用中文进行 Commit、PR、Issue、Review、业务注释、TODO/FIXME、测试报告、部署说明和变更说明。代码标识符使用规范英文，不使用拼音。

## 核心原则
- Baseline 是开发输入，不得静默改变。
- OpenAPI 是前后端接口合同。
- 没有证据不得写“已完成/已通过”。
- 不知道的业务规则标记 UNKNOWN 并提 Clarification/Change Request，不按行业经验自行补齐。
- 生产 Secret 不进入 Git、PR、日志、截图和聊天。
- 每个任务必须回传 Commit SHA、构建/测试结果、真实环境证据、已知问题和 Baseline 偏离说明。

## 当前 M01
打通 Enterprise → Project → API Key → Model Policy → Logical Model → Provider/Channel → ProviderAdapter → OpenAI-compatible API 的真实垂直链路。第一阶段只要求 stream=false，不提前进入 Billing、Fallback、Streaming 和 Payment。
