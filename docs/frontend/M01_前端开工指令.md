# M01 前端开工指令

> 本指令可直接交给前端开发人员或其开发 AI/Codex 执行。

你现在负责“智行官企业 AI 聚合服务平台”M01 前端改造。全程使用中文沟通、Commit、PR、Review、业务注释、测试报告和变更说明；组件、变量、路由、TypeScript类型等代码标识符使用规范英文，不使用拼音。

## 一、开工前必须读取
按顺序读取：
1. `docs/00_开发团队从这里开始.md`
2. `docs/governance/Baseline与变更管理规范.md`
3. `docs/governance/Git与PR规范.md`
4. `docs/frontend/00_前端开发启动说明.md`
5. `docs/frontend/前端开发执行Skill.md`
6. `docs/frontend/M01_前端开发任务包.md`
7. `docs/frontend/M01_前端资产复用矩阵.md`
8. `docs/frontend/M01_前端目录改造清单.md`
9. `contracts/openapi/` 中当前接口契约

## 二、工作模式
Frontend Mode：`BROWNFIELD_REFACTOR`

项目负责人提供的既有 Vue 工程是前端基线。必须保持现有整体样式、AppLayout、组件规范、权限模式、HTTP封装、Store/Router模式和测试体系，进行业务内容改造。

禁止重新搭建前端、换后台模板、换UI框架、擅自全局换主题或改成深色科技大屏。

## 三、工作目录与分支
共享开发机使用独立worktree：
```text
/workspace/ha-ai/frontend-worktree
→ feature/m01-frontend
```

既有Vue工程完整导入：
```text
frontend/
```

首次导入必须独立Commit，不得同时重构业务。

## 四、第一阶段
先完成“原始前端基线导入”：
1. 保持原目录结构；
2. 执行 pnpm install；
3. 执行 Build；
4. 执行 Type Check；
5. 执行 Vitest；
6. 有条件执行 Playwright；
7. 原工程已有失败必须原样记录，不得为了制造PASS顺手重构。

推荐Commit：
`基础(frontend): 导入既有Vue前端基线工程`

## 五、第二阶段：HA AI Shell
保持现有AppLayout，渐进新增：
- 企业端：项目/应用、API Key、模型权限、调用记录；
- 平台端：Logical Model、Provider、Channel。

M01建议路由：
```text
/ai/projects
/ai/projects/:projectId
/ai/projects/:projectId/api-keys
/ai/projects/:projectId/models
/ai/usage
/platform/ai/models
/platform/ai/providers
/platform/ai/channels
```

不得第一轮删除旧业务路由。

## 六、接口
- 保留现有 `src/api/http.ts`；
- Mock必须与OpenAPI完全同Schema；
- 后端可用后切真实API；
- 不维护Mock/Real两套字段；
- 前端按钮隐藏不等于后端权限；
- API Key完整Secret只允许创建成功时展示一次；
- REVOKED不得显示重新启用。

## 七、必须验证
- Build / Type Check；
- Vitest；
- 关键流程Playwright（环境允许时）；
- Loading / Empty / Error / Forbidden；
- 403 / 404 / 409 / 500；
- Model Policy授权/未授权；
- API Key首次Secret、禁用、撤销、过期；
- 桌面和窄屏基本可用；
- AppLayout、导航、公共组件无明显回归。

## 八、提交
Commit统一中文，例如：
```text
基础(frontend): 导入既有Vue前端基线工程
功能(frontend): 接入HA AI项目与API Key路由壳
测试(frontend): 增加API Key状态与错误页测试
```

完成后按开发证据模板回传 Commit SHA、PR、Build、Type Check、Test、截图、真实API联调、已知问题和Baseline偏离；未执行项写 `NOT_RUN`。
