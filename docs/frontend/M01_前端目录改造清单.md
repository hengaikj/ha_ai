# M01 前端目录改造清单

## 原则
只做渐进式业务换芯，不重建Layout和视觉系统。

## Phase F1：接入HA AI业务壳
1. 保留 `src/layouts/AppLayout.vue`。
2. 在现有路由机制中新增 HA AI M01 路由。
3. 菜单标题、页面标题、面包屑使用中文。
4. 新页面优先使用 `BasePageHeader`、`BaseDataTable`、`PermissionButton`、`BaseEmpty`、`TraceErrorAlert`。
5. 不删除旧路由，仅把新业务作为独立路径接入。

建议M01路径：
- `/ai/projects`
- `/ai/projects/:projectId`
- `/ai/projects/:projectId/api-keys`
- `/ai/projects/:projectId/models`
- `/ai/usage`
- `/platform/ai/models`
- `/platform/ai/providers`
- `/platform/ai/channels`

## Phase F2：API层
保留 `src/api/http.ts`，新增HA AI领域API模块。Mock与真实接口必须使用同一TypeScript类型和OpenAPI语义。

## Phase F3：权限
复用 `PermissionButton`、`PermissionGuard` 和 auth store。新增权限码必须来自当前权限设计，不自行发明超出Baseline的角色规则。

## Phase F4：Dashboard
复用 DashboardModule/DashboardChart。业务指标替换为调用量、Token、消费金额、成功率、响应时间、Provider健康等；M01只实现已有接口支持的指标，不能用假数据伪装生产能力。

## Phase F5：旧业务清理
M01功能和测试稳定后再建立旧业务删除PR。删除必须独立于HA AI功能PR，便于Review和回滚。

## 第一轮前端PR建议
PR-FE-01：只完成资产复用、HA AI Shell、路由与Mock接口骨架，不一次性迁移所有页面。
