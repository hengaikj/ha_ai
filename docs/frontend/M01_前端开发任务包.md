# M01 前端开发任务包 v1.1

## 目标
基于项目负责人指定的既有 Vue 工程进行 Brownfield 内容改造，保持整体视觉、Layout、组件和工程规范，不重新搭建前端。

## 第一步：既有资产审计
提交复用矩阵，至少覆盖：
- AppLayout / 导航 / 顶栏 / 面包屑；
- global.css / Design Token / 页面标题与描述规范；
- 通用表格、Dialog、表单、状态组件；
- PermissionButton / 路由守卫 / 权限机制；
- HTTP / Axios 封装；
- Pinia Store 模式；
- ECharts / DashboardModule；
- Loading / Empty / Error / Forbidden；
- Vitest / Playwright。

每项标记：KEEP / ADAPT / NEW / UNKNOWN / REMOVE-LATER。未经审计不得直接删除旧业务目录。

## 第二步：建立 HA AI Shell
保持现有 AppLayout 和整体样式，把业务导航渐进替换为 HA AI：
- 企业端：工作台、项目/应用、API Key、模型权限、项目额度、调用记录、费用与账单、成员与权限；
- 平台端：运营总览、企业管理、模型、Provider、Channel、路由策略、价格规则、调用观测、计费审计。

M01 只实现当前任务所需页面，其余可先建立明确占位，不得伪造已完成。

## 第三步：M01 页面
企业端：
- 项目列表/详情；
- API Key 管理；
- 模型权限；
- 调用记录基础页。

平台端：
- Logical Model；
- Provider；
- Channel 基础管理。

## 第四步：接口
先使用与 OpenAPI 完全一致的 Mock；后端可用后切换真实 API。不得维护一套 Mock 字段和另一套真实字段。

## 必测
- API Key Secret 首次展示；
- 禁用、撤销、过期；
- REVOKED 无重新启用入口；
- Model Policy 授权/未授权；
- 403 / 404 / 409 / 500；
- Loading / Empty / Error / Forbidden；
- 企业/项目数据范围；
- 关键页面桌面尺寸和移动/窄屏基本可用性；
- 改造后既有 Layout、导航、公共组件无明显回归。

## 明确禁止
第一阶段不换 UI 框架、不重做 Layout、不换后台模板、不全局改主题、不未经审计删除公共资产。

## 回传
Commit SHA、PR、Build、Type Check、Vitest/Playwright、关键页面截图、Mock/真实 API 联调记录、复用矩阵、已知问题、Baseline 偏离；未执行项写 NOT_RUN。
